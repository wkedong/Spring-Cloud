# 09 · 本地运行指南

> 目标：把全套微服务在你本机跑起来，并逐项验证（对应 docs/00 的验证入口清单）。

## 0. 前置条件

- JDK 17（本项目按 Java 17 编译，`java.version=17`）
- Maven 3.6+（或各模块自带的 `.mvn/wrapper`）
- MySQL 8.0（本机验证版本；Boot 4 带的是 **Flyway 11.14.1**，比 8.5 时代支持的 MySQL 版本范围更宽，教学环境沿用 8.0）
- Zipkin 二选一：Docker（推荐）或官方 exec jar

## 1. 准备 MySQL（三种方式任选）

**方式 A：docker compose（推荐，一键全带）**

```bash
docker compose up -d        # mysql(3306, 自动执行 sql/InitSQL.sql) + zipkin(9411)
```

**方式 B：已有 MySQL 8 实例**

```bash
mysql -uroot -p < sql/InitSQL.sql   # 建 spring_cloud_config / spring_cloud_demo 两库
```

**方式 C：临时实例（无 root 权限演示用）**

```bash
mysqld --initialize-insecure --datadir=/tmp/mysql-data
mysqld --datadir=/tmp/mysql-data --port=3306 &
```

## 2. 构建

```bash
mvn clean package -DskipTests

# 全仓单测（Surefire 3.5.6：-DfailIfNoTests 已改名，需配合 -Dsurefire.failIfNoSpecifiedTests=false）
mvn -B -Dtest='*Test,*Tests' -DfailIfNoTests=false -Dsurefire.failIfNoSpecifiedTests=false test
```

> 提示：改完依赖后必须 `mvn clean package`——Boot 4 的 repackage 不会刷新 fat jar 里的嵌套依赖，
> 只 `package` 不 `clean` 会静默复用 `BOOT-INF/lib` 里的旧包（本机实测）。

## 3. 启动 Zipkin（若用方式 B/C 准备数据库）

```bash
docker compose up -d zipkin
# 或下载官方发行版：
# curl -LO https://repo1.maven.org/maven2/io/zipkin/zipkin-server/3.4.2/zipkin-server-3.4.2-exec.jar
# java -jar zipkin-server-3.4.2-exec.jar
```

> 端口注意：早期自建 zipkin 模块曾用 6040，本版本统一为官方默认 9411。

## 4. 按依赖顺序启动服务（每条一个终端）

```bash
# ① 注册中心
java -jar eureka/target/eureka-0.0.1-SNAPSHOT.jar
# ② 配置中心（首次启动 Flyway 自动建 PROPERTIES 表并灌数据）
java -jar config/target/config-0.0.1-SNAPSHOT.jar
# ③ 服务提供者（可起两个实例观察负载均衡）
java -jar service-producer/target/service-producer-0.0.1-SNAPSHOT.jar --server.port=6070
# java -jar service-producer/...jar --server.port=6080   ← 第二实例
# ④ 四个消费者
java -jar service-consumer/target/service-consumer-0.0.1-SNAPSHOT.jar
java -jar service-consumer-feign/target/service-consumer-feign-0.0.1-SNAPSHOT.jar
java -jar service-consumer-ribbon/target/service-consumer-ribbon-0.0.1-SNAPSHOT.jar
java -jar service-consumer-ribbon-hystrix/target/service-consumer-ribbon-hystrix-0.0.1-SNAPSHOT.jar
# ⑤ 网关（最后启动，等注册表同步约 15~30s）
java -jar zuul/target/zuul-0.0.1-SNAPSHOT.jar
```

> IDE 里跑也可，但注意配置文件在 `src/main/resources/`（本分支已按 Maven 标准目录归位）。

## 6. 常见问题

| 现象 | 原因与解法 |
| --- | --- |
| 业务服务连不上 6010 | Boot 4 / 2025.1 已改用 `spring.config.import: optional:configserver:...` 接入配置中心，`optional:` 表示配置中心不可用也能启动（只是拿不到远端配置）；要读到远端配置仍按 eureka → config → 业务 的顺序先起配置中心 |
| `FlywayException: Unsupported Database` | MySQL 版本 > 8（如 9.x）；教学环境请用 MySQL 8.0，或临时 `--spring.flyway.enabled=false` 并手工建表 |
| `Public Key Retrieval is not allowed` | MySQL 8 认证插件问题，URL 已带 `allowPublicKeyRetrieval=true`；自改连接串时别删 |
| 调用报 `No servers available for service` | provider 未注册/刚重启注册表未同步——等 15~30s 再试；确认 eureka 控制台里有实例 |
| 网关 503 | 同上：`lb://` 目标服务在注册表里暂无实例 |
| gateway 启动报 MVC 冲突 | zuul 模块里混入了 `spring-boot-starter-web`（见 docs/06 迁移三坑） |
| `TraceCircuitBreaker cannot be cast ...` | 注入了具体类 `Resilience4JCircuitBreakerFactory`，改成抽象 `CircuitBreakerFactory`（见 docs/05） |
| multipart 报 `FileNotFoundException ... tmp` | `transferTo()` 之后再读原 MultipartFile；先转发后归档（见 docs/04） |

## 7. 全模块运行矩阵（第二阶段教学新增）

原来的 9 个模块是「核心链路」，第二阶段的 5 个新模块各自代表一类工程主题，**不依赖 Eureka/Config 也能单独跑**，
因此可以按需启停，不必把 14 个模块全拉起来。

```bash
# 第二阶段模块（各自独立，端口互不冲突）
java -jar springboot-basics/target/springboot-basics-0.0.1-SNAPSHOT.jar                  # 8010 H2 内存库，无需 MySQL
java -jar nacos-demo/target/nacos-demo-0.0.1-SNAPSHOT.jar                                # 8210/8211 需要 Nacos 3.x
java -jar sentinel-demo/target/sentinel-demo-0.0.1-SNAPSHOT.jar                          # 8220
java -jar stream-demo/target/stream-demo-0.0.1-SNAPSHOT.jar                              # 8230 需要 Kafka
java -jar security-demo/target/security-demo-0.0.1-SNAPSHOT.jar                          # 8240
java -jar seata-demo/seata-order/target/seata-order-0.0.1-SNAPSHOT.jar                   # 8250 需要 Seata Server + MySQL
java -jar seata-demo/seata-inventory/target/seata-inventory-0.0.1-SNAPSHOT.jar           # 8260
```

| 模块 | 端口 | 外部依赖 | 对应文档 |
| --- | --- | --- | --- |
| `springboot-basics` | 8010 | 无（H2 内存库） | 10~16 |
| `basics-audit-spring-boot-starter` | — | 无（被上面模块依赖） | 15 |
| `nacos-demo` | 8210 / 8211 | Nacos 3.x（8848） | 24 |
| `sentinel-demo` | 8220 | 可选 Sentinel Dashboard | 23 |
| `stream-demo` | 8230 | Kafka 9092 | 25 |
| `security-demo` | 8240 | 无 | 22 |
| `seata-demo`（order/inventory） | 8250 / 8260 | Seata Server 8091 + MySQL（Seata 客户端需显式补 Jackson 2 依赖，见 26） | 26 |

教学用的基础设施（都是单机可跑，代码库不依赖它们的容器化）：

| 设施 | 端口 | 用途 | 对应文档 |
| --- | --- | --- | --- |
| MySQL 8.0 | 3306 | 配置中心存储 + 业务库 + Seata 的 undo_log | 02 / 12 / 26 |
| Zipkin | 9411 | 链路追踪（`docker compose up -d` 或官方 exec jar） | 07 / 21 |
| Nacos 3.x（实测 3.2.4） | 8848（控制台 8080） | 注册中心 + 配置中心（standalone：`sh startup.sh -m standalone -Dloader.path=<目录>/plugins`，Derby 驱动在 plugins 里） | 24 |
| Kafka（KRaft） | 9092 | Stream 的消息中间件 | 25 |
| Seata Server | 8091 | 分布式事务协调器（file 模式注册） | 26 |
| Prometheus / Grafana | 9090 / 3000 | 指标采集与看板（配置在 `deploy/`） | 27 |

> **Nacos 必须用 3.x 服务端（实测 3.2.4，从 download.nacos.io 下载 `nacos-server-3.2.4.zip`）**：
> SCA 2025.1.0.0 带的客户端是 3.1.1，只配 2.x 服务端会「订阅成功但配置为空」——
> 日志 `[Nacos Config] config[dataId=...] is empty`，根因是 3.x 客户端把空命名空间归一化成 `public`，
> 而 2.x 服务端默认命名空间 ID 是空串，极易误判成「配置没发布」。
> 3.x 的运维变化：控制台独立在 **8080** 端口（API 仍 8848、gRPC 9848）；**v1/v2 配置 API 已移除**
> （`/nacos/v1/cs/configs` 返回 404），发布/读取改走 v3：`POST /nacos/v3/admin/cs/config`
> （form：`dataId`、`groupName`、`namespaceId`、`content`、`type`）、
> `GET /nacos/v3/client/cs/config?dataId=&groupName=&namespaceId=`；
> admin/console 鉴权默认开启（`nacos.core.auth.admin.enabled=true`、`nacos.core.auth.console.enabled=true`，
> 教学环境把它们关掉），且必须显式配置 `nacos.core.auth.server.identity.key/value`
> （否则启动报 `errCode: 50002, Empty identity`）。

## 8. 第二阶段新增的坑（都在本机实测踩过）

| 现象 | 原因与解法 |
| --- | --- |
| 启动即失败：`InvalidConfigDataPropertyException: Property 'spring.profiles.active' imported from location 'class path resource [application-peer1.yml]' is invalid in a profile specific resource` | Boot 2.4+ 起 **profile 特定文件里不允许再声明 `spring.profiles.active`**。用 `--spring.profiles.active=peer1` 或 `spring.config.activate.on-profile` 激活（见 docs/11） |
| `NoSuchBeanDefinitionException: No qualifying bean of type 'ReactiveDiscoveryClient'` | 自定义 LoadBalancer 的实例供应器写成了 `withDiscoveryClient()`；servlet 栈 + Eureka 阻塞客户端要用 `withBlockingDiscoveryClient()`（见 docs/18） |
| 自研 GlobalFilter「完全没生效」且无任何报错（限流不触发、连响应头都没有） | 过滤器不在主应用类所在包或其子包内，没被扫描；用 `/actuator/beans` 确认 bean 是否存在（见 docs/19） |
| Feign 调用失败抛 `NoFallbackAvailableException` | 开了 `spring.cloud.openfeign.circuitbreaker.enabled=true`（旧键 `feign.circuitbreaker.enabled` 在 2025.1 静默失效）后所有调用都过熔断器，客户端没配 fallback 就会抛它——它不是业务异常（见 docs/17） |
| 编译报 `程序包 io.github.resilience4j.bulkhead 不存在` / 找不到 `Decorators` | `spring-cloud-starter-circuitbreaker-resilience4j` 不含这些模块，额外加 `io.github.resilience4j:resilience4j-all`（见 docs/20） |
| 重启服务报 `PortInUseException: Port 7030 is already in use` | 旧进程还在优雅停机（可能耗时数十秒）。先 `lsof -ti tcp:7030 \| xargs kill`，再**轮询等到端口真正空闲**后启动 |
| 配置中心启动报 `Duplicate entry '1' for key 'properties.PRIMARY'` | 配置表里已有数据时重复灌数（Flyway 迁移脚本重跑）；教学环境用 MySQL 8.0，或先清空 `config` 库，或临时 `--spring.flyway.enabled=false` |
| `/actuator/circuitbreakers`、`/actuator/gateway/routes` 返回 404 | 端点默认不暴露，需要 `management.endpoints.web.exposure.include`；gateway 端点另外需要 `management.endpoint.gateway.access: read-only`（Gateway 5 已删除 `enabled`，改为 access：read-only / unrestricted / none） |

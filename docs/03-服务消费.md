# 03 · 服务消费（RestTemplate + LoadBalancer）

> 模块：`service-consumer/`（7010）与 `service-consumer-ribbon/`（7030）。
> 版本对照：Ribbon 依赖 → Spring Cloud LoadBalancer，业务代码零改动。

## 学什么

有了注册中心之后，消费方怎么「按服务名」调 HTTP 接口？标准答案就一行注解：

```java
@Bean
@LoadBalanced              // 给 RestTemplate 装上"服务名 → 负载均衡地址"的能力
RestTemplate restTemplate() {
    return new RestTemplate();
}
```

```java
restTemplate.getForObject("http://service-producer/testGet", String.class);
//            ↑ 不是真实域名，是 Eureka 里的服务名
```

`@LoadBalanced` 会给 RestTemplate 注入拦截器：把 `service-producer` 解析成
注册表里的实例列表，按负载均衡策略挑一台发请求。两个消费模块代码相同，
分别演示「裸消费」与「显式负载均衡消费」。

> 注意：升级后这个 Bean 还要**挂 `ObservationRegistry`**，否则跨服务链路会断（见下节「2025.1 的变化」）。

## 2021.0.x 的变化：Ribbon 退役，LoadBalancer 上位

- 旧版靠 `spring-cloud-starter-ribbon`（Netflix Ribbon）实现上述拦截；
- 2021.0.x 改为 `spring-cloud-starter-loadbalancer`（Spring Cloud LoadBalancer）；
- **业务代码零改动**：`@LoadBalanced RestTemplate` 的语义不变；
- 默认策略轮询（`RoundRobinLoadBalancer`），旧 Ribbon 的重试/分区等高级策略要在
  LoadBalancer 里另配（`spring.cloud.loadbalancer.*`）。

> 目录名 `service-consumer-ribbon` 是历史名（沿用早期工程结构）：真正的 Ribbon 已不存在——
> 这本身就是一次很好的「组件生命周期」教学。

## 2025.1 的变化：RestTemplate 要挂 `ObservationRegistry`（否则链路断）

升级到 Boot 4.0.8 / Spring Cloud 2025.1.3 后，`RestTemplate` 发出的请求**不再自动带上链路追踪信息**：
必须显式给它设置 `ObservationRegistry`，否则 traceId 不会写进下游请求头
（Micrometer Tracing 默认用 W3C `traceparent`），Zipkin 里下游会**另起一条新 trace**。

```java
@Bean
@LoadBalanced
RestTemplate restTemplate(ObservationRegistry observationRegistry) {  // io.micrometer.observation.ObservationRegistry
    RestTemplate restTemplate = new RestTemplate();
    restTemplate.setObservationRegistry(observationRegistry);         // 这一行 = 客户端 span + 传播头
    return restTemplate;
}
```

另一条路是用 Boot 的 `RestTemplateBuilder`（它会自动挂 `ObservationRestTemplateCustomizer`），
但 Boot 4 把它从 `org.springframework.boot.web.client.*` 挪到了
`org.springframework.boot.restclient.RestTemplateBuilder`，并拆进独立模块 `spring-boot-restclient`
（`spring-boot-starter-web` 不再传递它），所以本仓库选了上面这种**零新增依赖**的写法。

> **实测**：修复前 4 个消费者在 Zipkin 里都是**单服务 trace**（producer 侧生成了新 traceId，仅高 32 位相同）；
> 给 RestTemplate 挂上 `ObservationRegistry`（Feign 侧则补 `feign-micrometer`）后，各消费者都出现
> `[服务A, service-producer]` 的**同一条 trace**，客户端 span 名为 `http get`。

## multipart 文件转发（consumer 的 testFile）

`ConsumerController#testFile` 演示了 RestTemplate 转发 multipart 的经典姿势：
收到 `MultipartFile` → 落临时盘 → `FileSystemResource` 装进 `MultiValueMap` → POST 给 producer。
升级时做了两处修正：`D:\tempFile` 硬编码改为跨平台临时目录；`e.printStackTrace()` 改 slf4j。

## 思考点

- `@LoadBalanced` 解析的是**服务名**，因此 URL 里不能写端口；
- RestTemplate 是阻塞式 IO，调用链一长线程占用会放大——高并发场景应考虑 OpenFeign
  （下一章，声明式且可插拔）或 WebFlux/WebClient。

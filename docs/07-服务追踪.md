# 07 · 服务追踪（Micrometer Tracing + 官方 Zipkin）

> 模块：追踪能力分布在各业务模块；独立的 `zipkin/` 模块已删除，改用官方 Zipkin（9411）。
> 版本对照：埋点组件 Sleuth 3.1（2021.0.x）→ **Micrometer Tracing**（Boot 4.0.8 / Spring Cloud 2025.1.3）；
> 自建 Zipkin（库形态，已废弃，曾用 6040）→ 官方独立发行版（9411）。

## 学什么

一次用户请求穿过网关 → 消费者 → 生产者，出问题时想回答「慢在哪、错在哪一跳」，
需要**分布式链路追踪**：每次请求分配全局唯一 traceId，跨服务透传；每一跳记一个 span
（带耗时、标签）；所有 span 汇总到 Zipkin，按 traceId 还原完整调用链瀑布图。

- **埋点**：2021.0.x 时代是 **Sleuth**（3.1.x，本仓库已不存在）；现役是 **Micrometer Tracing**
  （micrometer-tracing 1.6.x + Brave 桥接）——为 RestTemplate/Feign/MVC/gateway 等组件注入 trace 信息
  （HTTP header 透传），概念与 Sleuth 相同、API 不同；
- **Zipkin**：负责展示——收集 span、按 trace 拼瀑布、看依赖拓扑。

## 关键架构变化：Zipkin 不再是 Spring Boot 应用

老 demo 用 `io.zipkin.java:zipkin-server` 把 Zipkin **嵌成自己项目里的一个 Spring Boot 模块**。
Zipkin 2.14 起官方停止提供这种库形态，改为独立发行版（原生进程/容器）。
因此 develop 分支：

- 删除了 `zipkin/` 自建模块（库形态已废弃，改由官方独立发行版承担）；
- 新增根目录 `docker-compose.yml`，一条命令拉起 MySQL + 官方 Zipkin；
- 业务模块只需保留一个依赖，**零代码改动**：

```xml
<!-- 旧（Sleuth 时代，2021.0.x）—— 这两个 starter 都已不存在：
     spring-cloud-starter-sleuth / spring-cloud-sleuth-zipkin -->

<!-- 新（Boot 4）：链路追踪的自动配置不再随 actuator 一起来，改由 spring-boot-starter-zipkin 一次带齐 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-zipkin</artifactId>
</dependency>
```

`spring-boot-starter-zipkin` 内含 `spring-boot-micrometer-tracing`、`spring-boot-micrometer-tracing-brave`、
`spring-boot-zipkin` 与 `micrometer-tracing-bridge-brave`——Sleuth 时代的两个 starter 都不用再加。

配置（Sleuth 的键已随 Sleuth 一起消失，现役是 `management.*` 下的两组键）：

```yaml
# 旧（Sleuth 时代，2021.0.x）：spring.zipkin.base-url + spring.sleuth.sampler.probability —— 均已失效
management:
  tracing:
    sampling:
      probability: 1.0                              # 采样率：1.0 = 全采样（教学环境）
  zipkin:
    tracing:
      endpoint: http://localhost:9411/api/v2/spans  # 上报地址要写到 v2 API 路径（官方独立发行版默认 9411）
```

> 教学环境全采样看全量链路；生产环境通常 0.01~0.1（10% 甚至 1%）控制上报成本。

## 2025.1 的变化：Sleuth 退役，Micrometer Tracing 上线

Sleuth 在 Boot 3 起就被 **Micrometer Tracing** 取代；本仓库升到 Boot 4.0.8 / Spring Cloud 2025.1.3 后，
链路追踪的自动配置**不再随 actuator 一起来**，由 `spring-boot-starter-zipkin` 提供（见上）。
传播与埋点的默认行为也换了一套，下面三点直接决定「链路是通的还是断的」：

1. **传播类型默认 W3C**：本机抓到的上游请求头是 `traceparent: 00-<traceId>-<spanId>-01`，
   不再是 Sleuth 时代的 `X-B3-*`；
2. **`RestTemplate` 必须挂 `ObservationRegistry`**（`restTemplate.setObservationRegistry(registry)`），
   **Feign 必须显式引 `feign-micrometer`**——少任何一条，客户端 span 就没了，
   traceId 也不会写进下游请求头（细节见 [04-声明式调用Feign](04-声明式调用Feign.md)、[03-服务消费](03-服务消费.md)）；
3. **注解式埋点换 API**：Sleuth 的 `@NewSpan`/`@SpanTag` 已不存在，改用 `@Observed`，
   且必须显式打开 `management.observations.annotations.enabled: true`（Boot 3.2+ 起注解默认不生效），
   打开后 Zipkin 里才会出现 `producer-annotated-span`（另有编程式埋点生成的 `producer-custom-span`）。

> **实测（跨服务链路修复）**：修复前 4 个消费者在 Zipkin 里都是**单服务 trace**——
> producer 侧生成了新 traceId，仅高 32 位相同；补上 `feign-micrometer`、给 RestTemplate 挂上
> `ObservationRegistry` 后，4 个消费者各自都出现 `[服务A, service-producer]` 的**同一条 trace**，
> 客户端 span 名为 `http get`。

## 动手验证

```bash
# 启动 Zipkin（任选其一）：
docker compose up -d zipkin
# 或无 Docker：
# java -jar zipkin-server-3.4.2-exec.jar --server.port=9411

# 制造一条跨 3 层的链路：网关 → consumer → producer
curl http://localhost:6050/service-consumer/testGet

# 打开 UI 查询：
open http://localhost:9411
# 选择 service-consumer，Run Query → 点开 trace，
# 应看到 gateway/server、consumer/client+server、producer/client+server 的瀑布，共享同一 traceId
# 客户端 span 名为 http get；修复前每个消费者在这里都是「单服务 trace」，下游另起了一条新 trace
```

也可以直接确认日志埋点。下面是**旧 Sleuth 3.1 的格式（仅作历史对照）**——现役 Micrometer Tracing
的日志关联格式与它不同（字段仍是 traceId/spanId）：

```
INFO [service-consumer, 6c2f..., 6c2f..., true] ===<call testGet>===
      └ 应用名            traceId   spanId   采样标记
```

## 思考点

- 采样率不是「丢功能」：Zipkin 看的是概率样本 + 聚合视图，高频接口低采样率同样能定位慢调用；
- span 的 parent 关系由 header 透传维护——**默认是 W3C 的 `traceparent`**（不再是 Sleuth 时代的 `X-B3-*`），
  实测抓到的上游头就是 `traceparent: 00-<traceId>-<spanId>-01`；
- 但「自动包装」不再是默认福利：`RestTemplate` 必须挂 `ObservationRegistry`、Feign 必须显式引
  `feign-micrometer`，否则客户端 span 缺失、传播头写不出去，下游另起一条新 trace（本仓库升级时正是这个坑）；
  自己 new 一个「裸」客户端对象发请求，链路同样会断（常见面试题）；
- 更进阶：本仓库已升级到 **Boot 4.0.8 / Spring Cloud 2025.1.3**，Sleuth 彻底退役、由 **Micrometer Tracing**
  取代（API 不同、概念相同），注解式埋点也从 `@NewSpan`/`@SpanTag` 换成了 `@Observed`。

# 06 · 服务网关（Zuul → Spring Cloud Gateway）

> 模块：`zuul/`，端口 6050；实现已是 Spring Cloud Gateway。
> 版本对照：本篇内联 Zuul 1.x 旧写法与 Gateway 新写法，全量清单见 [08-升级迁移指南](08-升级迁移指南.md)。

## 学什么

网关是微服务的唯一入口：鉴权、限流、路由、日志聚合都在这里做，业务服务不直接暴露给外网。
Zuul 1.x 是同步阻塞（每个请求占一个 Servlet 线程），Netflix 已停止维护；
Spring Cloud Gateway 基于 **WebFlux + Reactor Netty**，非阻塞、支持少量线程扛高并发，
是官方指定的继任者。

## 2021.0.x 的写法迁移

**旧（Zuul 1.x 写法）**：

```java
@EnableZuulProxy
@SpringCloudApplication      // = @SpringBootApplication + discovery + circuit breaker(Hystrix)
public class ZuulApplication { ... }
```

```yaml
# 老版习惯：开 discovery locator 后 zuul 按 serviceId 自动转发（甚至不用配路由）
zuul:
  ignored-headers: Access-Control-Allow-Credentials, Access-Control-Allow-Origin
```

**新（develop 分支）**：

```java
@SpringBootApplication        // Gateway 无需开启注解
@EnableDiscoveryClient
public class GatewayApplication { ... }
```

路由配置整体迁移（`zuul.routes.*` → `spring.cloud.gateway.server.webflux.routes.*`，5.x 的前缀下移见下节）：

```yaml
spring:
  cloud:
    gateway:
      server:
        webflux:
          discovery:
            locator:
              enabled: true              # 按服务 id 自动生成路由 /service-producer/** 等
              lower-case-service-id: true
          routes:
            - id: service-producer
              uri: lb://service-producer # lb:// = 从注册中心负载均衡
              predicates:
                - Path=/api/producer/**
              filters:
                - StripPrefix=2   # 剥掉 /api/producer 两段再转发（StripPrefix 按"段"计数，不是按字符）
```

## 2025.1 的变化（Gateway 5.0.x：starter 更名 + 前缀下移一层）

| 变化点 | 旧（3.1.x） | 新（5.0.x） |
| --- | --- | --- |
| starter 坐标 | `spring-cloud-starter-gateway` | `spring-cloud-starter-gateway-server-webflux` |
| 配置前缀 | `spring.cloud.gateway.*` | `spring.cloud.gateway.server.webflux.*` |
| 网关 actuator 开关 | `management.endpoint.gateway.enabled` | `management.endpoint.gateway.access: read-only` |

旧前缀与旧开关在 5.x **不报错，只是什么都不生效**（路由表为空、`/actuator/gateway/routes` 空数组），
排查时先确认前缀层数对不对。

```bash
# 开关改成 access: read-only 之后，可以在线查看路由表：
curl -s http://localhost:6050/actuator/gateway/routes | python3 -m json.tool
```

## 迁移三坑（必读）

1. **WebFlux 与 MVC 冲突**：Gateway 模块**禁止**引入 `spring-boot-starter-web`，
   否则启动报 `Spring MVC found on classpath, which is incompatible with Spring Cloud Gateway`；
2. **`@SpringCloudApplication` 已移除**：它内含的 Hystrix 语义在新架构下由
   CircuitBreaker filter（`spring.cloud.gateway.server.webflux.httpclient.*`）按需实现；
3. **Predicates/Filters 词汇表**：Zuul 的 pre/post filter 对应 Gateway 的 filter 链，
   断言（Path、Method、Header…）+ 过滤器（StripPrefix、Retry、RateLimit…）是新的核心词汇。

## 动手验证

```bash
# 自动发现路由（等价旧 Zuul 行为；locator 生成的是小写服务名，实测大写 SERVICE-PRODUCER 不通）：
curl http://localhost:6050/service-consumer/testGet
curl http://localhost:6050/service-producer/testGet
# 显式路由 + 前缀剥离（/api/producer/testGet → producer /testGet）：
curl http://localhost:6050/api/producer/testGet
# 前缀路由调用熔断链路（网关→hystrix→producer）：
curl http://localhost:6050/api/consumer/testHystrix 2>/dev/null || \
curl http://localhost:6050/service-consumer-ribbon-hystrix/testHystrix
```

## 思考点

- 为什么 Gateway 要换 WebFlux：网关是 IO 密集型（转发而已，几乎不耗 CPU），
  非阻塞模型用少量线程处理大量并发连接，这正是网关的负载画像；
- 生产落地时通常再加全局过滤器做鉴权（`GlobalFilter`）与限流（`RequestRateLimiter` + Redis）。

# 02 · 配置中心（config）

> 模块：`config/`，端口 6010。
> 新旧对照：`master` 分支同名目录为 Edgware 旧版实现（Flyway 5.x + 老式 starter）。

## 学什么

配置（数据库地址、开关、密钥）散落在每个服务本地是反模式：改一次要全量重启。
Config Server 把配置集中到一处（本模块选了 **JDBC 后端**：配置存 MySQL 表，
比 Git 后端多一层「配置也能有数据库事务/管理界面」的想象空间），客户端按
`应用名 + profile + label` 三元组拉取自己的配置。

## 核心代码与配置解析

`ConfigApplication.java`：

```java
@EnableConfigServer     // 打开配置服务端
@EnableDiscoveryClient  // 同时把自己注册进 Eureka
@SpringBootApplication
public class ConfigApplication { ... }
```

配置读取逻辑全在 yml：

```yaml
spring:
  profiles:
    active: jdbc                     # 使用 JDBC 后端（注释掉的 git 段是另一后端示例）
  cloud:
    config:
      server:
        jdbc:
          sql: SELECT `KEY`, `VALUE` from PROPERTIES
               where APPLICATION=? and PROFILE=? and LABEL=?
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/spring_cloud_config?...
```

PROPERTIES 表由 **Flyway** 在启动时自动建表并灌入种子数据
（`src/main/resources/schema/V1.0__Base_version.sql` 建表、V1.1 灌数据）——
所以第一次启动 config 之前，只需要先有 `spring_cloud_config` 库（见 `sql/InitSQL.sql`）。

## 2021.0.x 的变化（本模块是「无声坑」最多的模块）

| 变化点 | 说明 |
| --- | --- |
| Flyway 5.0.3 → 8.5.13 | 前缀 `flyway.*` → `spring.flyway.*`；`locations: /schema` → `classpath:/schema` |
| flyway-mysql 必须单独引入 | Flyway 8.2 起 MySQL 方言拆出，缺包报 `Unsupported Database: MySQL` |
| MySQL 驱动 5.1 → 8.0 | 坐标 `com.mysql:mysql-connector-j`，驱动类 `com.mysql.cj.jdbc.Driver`，URL 建议补 `serverTimezone` |
| bootstrap 默认失效 | Boot 2.4+ 需 `spring-cloud-starter-bootstrap`（本模块服务端用 application.yml，未受影响；**业务模块**受影响） |

## 动手验证

```bash
# 1. 准备数据库（见 09-本地运行指南）
# 2. 启动配置中心
java -jar config/target/config-0.0.1-SNAPSHOT.jar
# 3. 直接按 REST 契约拉配置：/{application}/{profile}/{label}
curl http://localhost:6010/service-producer/dev/develop
# 应返回 propertySources 中含 name = test-dev-develop 的 JSON
# 4. 启动 producer 后验证配置真的注入了：
curl http://localhost:6070/testConfig
# → "Hello, Spring Cloud! My port is 6070 ConfigName is test-dev-develop"
```

## 思考点

- 客户端拉配置发生在**启动阶段**（bootstrap 上下文），改 PROPERTIES 表后业务服务重启才能生效；
  想不重启就生效，要引入 `@RefreshScope` + `/actuator/refresh`（可作为练习）；
- `spring-cloud-starter-config` 在客户端侧拉取配置；配置中心自己也要注册进 Eureka，
  这样才能升级到 discovery-first 模式（客户端不再需要知道 config 的地址）。

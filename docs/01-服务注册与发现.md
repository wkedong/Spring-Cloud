# 01 · 服务注册与发现（eureka）

> 模块：`eureka/`，端口 6060。
> 版本对照：Edgware 旧写法 → 2025.1 现役写法（Netflix Eureka 5.0.2），汇总见 [08-升级迁移指南](08-升级迁移指南.md)。

## 学什么

微服务架构里，服务实例的地址是动态的（扩缩容、漂移、重启换端口），不能靠硬编码互相调用。
Eureka 解决的就是「**谁在线、在哪里**」：每个服务启动时把自己注册进去（register），
并定期拉取其它服务的注册表（fetch registry）；服务间调用时只用「服务名」，地址由注册中心解析。

## 核心代码解析

`EurekaApplication.java` —— 服务端只需一个注解：

```java
@EnableEurekaServer     // 打开 Eureka 服务端（注册表、租约、自我保护）
@SpringBootApplication
public class EurekaApplication {
    public static void main(String[] args) {
        SpringApplication.run(EurekaApplication.class, args);
    }
}
```

`application.yml` 里的三个关键开关（单机演示的标准姿势）：

```yaml
eureka:
  client:
    registerWithEureka: false   # 注册中心自己不注册自己
    fetchRegistry: false        # 也不需要拉取注册表（它是源头）
    serviceUrl:
      defaultZone: http://localhost:6060/eureka/
```

## 2021.0.x 的变化

- starter 由 `spring-cloud-starter-eureka-server` 更名 `spring-cloud-starter-netflix-eureka-server`
  （只是坐标更名，注解/配置不变）；
- 2021.0.x 的 Eureka client 2.x 改用 `RestTemplate` 转发注册请求（旧版是 Jersey），
  属于内部实现，教学无感。

## 2025.1（Netflix Eureka 5.0.2）的两个必改开关

Eureka 客户端从 3.1.x 升到 **5.0.2** 后，下面的开关**必须显式关掉**，否则启动失败或端点 500：

```yaml
eureka:
  client:
    jersey:
      enabled: false      # 必改①：5.0.2 移除了 Jersey 传输的配置 Bean，而该开关仍默认 true
    refresh:
      enable: false       # 必改②：关掉 refresh scope 的 Eureka 客户端
```

- `eureka.client.jersey.enabled: false`：Netflix 5.0.2 移除了 Jersey 传输的配置 Bean，
  但该开关仍默认 `true`，客户端启动直接失败：
  `No qualifying bean of type 'com.netflix.discovery.shared.transport.jersey.TransportClientFactories'`；
- `eureka.client.refresh.enable: false`：默认的 Eureka 客户端是 refresh scope 的 Bean，
  `/actuator/health`、`/actuator/refresh` 触发它重建时会抛 `BeanCreationException`（内部 NPE），
  两个端点直接 500；关掉后走普通单例客户端。

> **实测**：修复前 Eureka 客户端的 `/actuator/health` 与 `POST /actuator/refresh` 都是 500；
> 加上 `eureka.client.refresh.enable: false` 后均为 200（`refresh` 返回 `[]`）。
> 注册中心自身（`eureka/`）也显式写了这两个开关，避免日后改成「自注册」时踩同一颗雷。

## 动手验证

```bash
mvn -pl eureka -am package -DskipTests
java -jar eureka/target/eureka-0.0.1-SNAPSHOT.jar
# 打开 http://localhost:6060 看到 Eureka 控制台；
# 之后依次启动 producer/consumer，再回控制台看实例出现：
curl -H "Accept: application/json" http://localhost:6060/eureka/apps

# 客户端侧：上面两个开关关掉后，健康检查与刷新端点应正常（以 producer 6070 为例）
curl -s http://localhost:6070/actuator/health           # → {"status":"UP"}
curl -s -X POST http://localhost:6070/actuator/refresh  # → []（变更键列表）
```

## 思考点

- `registerWithEureka=false` + `fetchRegistry=false` 是「单机注册中心」写法；
  集群部署时两个都开、`defaultZone` 互指即可（本项目 producer 的 application-peer*.yml
  是 2019 年做多实例实验的遗留，教学上建议直接用 `--server.port` 启动多实例）；
- 自我保护机制（self-preservation）：短时间大量实例掉线时 Eureka 会保留注册表——
  这是 AP 系统的典型取舍，开发环境可 `enable-self-preservation: false` 快速看到实例下线。
